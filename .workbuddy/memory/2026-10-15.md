## 服务器 Python 3.9 兼容改造（部署踩坑）

- 用户在服务器执行 `python3 -m venv .venv && pip install -e .` 报 `Package 'chanpicker' requires a different Python: 3.9.25 not in '>=3.11'` —— 项目 `requires-python` 写死 `>=3.11`，服务器是 3.9.25。

## 修正 westock 安装与授权文档（用户指出「这个不对」）

- 原 DEPLOY 写的 `bash /path/to/westockdata/scripts/setup.sh` 与「`westock auth status` 会输出链接」不准确/不可执行。查证 `westockdata` 技能包 SKILL.md + scripts/setup.sh + references/auth.md 后重写。
- 真实事实：
  - 安装入口有三个：`bash scripts/setup.sh`（macOS/Linux）、`powershell setup.ps1`（Windows）、`node scripts/setup.cjs`（Node≥18），**均在技能包 `westockdata/scripts/` 目录内**；服务器默认没有该包，需 `scp` 脚本过去跑，或本地装好后把单文件二进制 `~/.local/bin/westock` 拷到 `/usr/local/bin`。
  - setup.sh 零参数执行，自动识别 linux/darwin × amd64/arm64，强制 SHA256 校验，**只写二进制、不改 PATH/不写 shell 配置**，默认装到 `~/.local/bin`（`WESTOCK_INSTALL_DIR` 可覆盖）。
  - 授权是设备码流程：`westock auth status` → `READY` / `AUTH_REQUIRED:<url>`（5 分钟有效，任意电脑浏览器打开）→ 轮询 `westock auth fetch` 直到 `TOKEN_READY`；**轮询期间禁止再跑 `auth status`**（会重新 issue 覆盖 device code，导致刚扫的码作废）。兜底 `westock auth set "<key>"`，退出 `westock auth clear`。
  - 凭证在 `~/.westock`（`WESTOCK_HOME` 可覆盖），systemd 必须同用户。
- 代码顺带加固：`provider.WESTOCK_BIN_CANDIDATES` 增加 `/usr/local/bin/westock`（服务器常见安装位）。
- systemd unit 文档补 `Environment=WESTOCK_HOME=` 与 PATH 含 `/home/chanpicker/.local/bin`。

## 多周期（30分/15分）+ 卖点（一卖/二卖）改造方案（仅方案，未编码）

- 用户要求：日线之外增加 30 分钟 / 15 分钟模型，并在 K 线增加一卖/二卖关键点位。按用户习惯「先给方案等确认」，只产出 `改造方案-多周期与买卖点.md`，未动代码。
- **数据源实测结论（重要，决定架构）**：
  - `kline --period` 支持 m1/m5/m15/m30/m60/m120；日线 `--limit 400` 可得 400 根。
  - **分钟周期 `--limit` 无效**（m30 `--limit 500` 只返回当日 8 根），必须 `--start/--end`。
  - 实际可得：m30 = 72 根（约 9 个交易日），m15 = 144 根（约 9 个交易日）；官方跨度上限 m15=20 天、m30=30 天；分钟数据仅留近 1 个月。
  - 分钟周期**支持批量**（实测 2 只 m30 成功）。
  - 连续调用会限流（返回「请求过于频繁」）。
- 由此拍板的设计：日线仍是选股主周期；分钟只做**区间套确认 / 日内择时**，不做全市场选股（样本仅 9 天，中枢不可靠）；分钟只跑「按需单只 + 关注圈小批量」避免限流。
- 另一口径决策：**卖点不参与 `qualifies` 判定**，走独立 `risk_signals` 字段展示（买点=选股，卖点=持仓管理，混在布尔值里语义会崩）。
- 卖点定义（镜像买点）：一卖=连续上升段顶背驰 + 高点在中枢 ZG 上方 + 顶分型次日确认；二卖=一卖后反弹不创新高且力度衰减；三卖预留。
- 迁移风险：`bars` 表需加 `period` 列并回填 `day`，改造前必须备份 `data/chanpicker.db`，否则 300 只日线缓存失效触发全量重拉。
- 分期建议：P1 卖点（日线）→ P2 多周期数据层 + 单只/关注圈分钟分析 → P3 级别联立共振标记。

### 计划外发现并修复的重大缺陷：共享 SQLite 连接并发读串扰
- 现象：前端 `Promise.all` 并发请求 `/api/market/pools` 与 `/api/market/risk` 时互相读到对方游标——`trading_dates` 变空数组或混入空字符串。
- 根因：单个 `sqlite3` 连接（`check_same_thread=False`）服务 FastAPI 线程池，**写有锁、读无锁**；sqlite3 连接非线程安全。
- 修复：`threading.Lock` → `RLock`；新增模块级 `_sync` 装饰器，给 28 个访问连接的方法统一加锁；启用 `PRAGMA journal_mode=WAL` + `busy_timeout=30000`。
- 回归用例 `tests/test_backend_store.py`（迁移 3 例 + 并发 1 例，5 线程读写 1.5s）。已用「去掉锁必失败」反向验证用例有效。
- **教训：sqlite + FastAPI 同步端点必须给读也加锁。**

## 补充：默认首页空白（用户报障）

- 现象：`http://127.0.0.1:8787` 打开一片空白，必须手点一次页签才有数据。
- 复现（无头 Chrome + CDP）：四个 `<section>` 全是 `display:none`、`main` 可见高度 40、`body` 文本长度 0，但 `tableRows: 43`、`scanMeta` 已填充 → **数据取回来了，只是没渲染**。
- 根因：`git show HEAD:frontend/index.html` 确认自首版起，导航按钮 `<button data-tab="market" class="active">` 有 `active`，而 `<section class="tab" id="tab-market">` **没有**；CSS 是 `section.tab{display:none}`，且「给 section 加 active」这件事只写在 click 回调里，不点就永远不会发生。
- 修法：页签切换收敛为唯一入口 `switchTab(name)`（同时改按钮高亮 + 区块显隐 + 触发该页数据加载），HTML 补 `class="tab active"`，初始化 `activateDefaultTab()` 以按钮上的 `active` 为准、缺省退回第一个；`analyzeFrom()` 里的 `.click()` 也换成 `switchTab('stock')`。
- 防复发：新增 `tests/test_frontend_contract.py`（6 例静态契约：nav 集合 == section 集合、恰好一个 active 且指向同一页签、默认页是 market、CSS 仍隐藏未激活块、切换必须走 switchTab 且初始化真的调用）。**已做反向验证**：摘掉 section 的 active / 删掉 `activateDefaultTab()` / 摘掉 nav 的 active / 多给一个 section 加 active，四种变异各自都能让测试红。
- 写测试时自己踩的两个坑（易复发）：① 解析 `class="active"` 不能 `attrs.split()` 后判 `'active' in ...`（拿到的是 `class="active"` 整体令牌）；② `unittest` 的 `assertRegex(text, regexp, msg)` **第三个位置参数是 msg 不是 flags**，要行首锚定必须传 `re.compile(p, re.M)`。
- 最终状态：单测 **28/28**（Python 3.13 与 3.9.25 双版本）；浏览器复验初始加载 market=block、其余 none，跨页跳转（点表格「查看结构」→ 个股查询，input 填 sh600111、K 线画布 1 个、结论 `verdict yes`）、返回市场均正常，可见页签恒为 1，控制台零错误。
