# ChanPicker · 缠论 A 股选股系统

以缠论为基座的 A 股日线级别选股系统：**背驰 + 一买 → 关注圈 → 持续跟踪 → 二买提示机会**。

## 架构

```
frontend/index.html        前端单页应用（市场扫描 / 个股查询 / 关注圈 / 三日买卖点池，ECharts K线结构图）
backend/
  app.py                   FastAPI 服务（REST API + 静态托管前端）
  service.py               业务编排（单只分析 / 全市场扫描任务 / 关注圈 / 买卖点池）
  provider.py              westock CLI 数据适配（多周期取数 + 批量拉取 + 限流退避重试 + markdown 解析）
  store.py                 SQLite 持久化（多周期K线缓存 / 信号 / 关注圈 / 扫描任务）
src/chanpicker/
  core.py                  缠论核心引擎（分型 → 笔 → 中枢 → 背驰 → 一买/二买/三买/一卖/二卖 → 关注圈状态机）
  cli.py                   命令行入口（scan / watch，可脱离服务独立使用）
tests/                     单元测试（引擎逻辑 + 数据解析 + 存储迁移与并发一致性）
data/chanpicker.db         SQLite 数据库（自动创建）
run.sh                     一键启动脚本
```

## 环境要求

Python **3.9+**（已在 3.9.25 与 3.13 上实测通过；类型标注统一使用 `Optional`/`Union`，不依赖 3.10+ 语法），以及已授权可用的 westock CLI。

页面四个标签：

- **市场扫描**：点击「扫描全部A股」→ 进度条（含预计剩余时间）→ 自动列出近30日触发「一买」与「二买」的股票；旁边「仅沪深300（快速）」用于秒级验证。所有表格支持**点击表头排序**，默认按二买日 / 信号日降序。扫描卡片下方是**历史买点成功率**面板
- **个股查询**：输入代码（如 `sh600519`）→ 是否符合结论 + K线结构图。支持 **日线 / 30分钟 / 15分钟** 一键切换；图中标注分型、笔、中枢、一买/二买/三买（向上图钉）与**一卖/二卖（向下箭头，标在关键高点）**，并叠加**背驰段**（灰虚线=前段力度，彩线=背驰段，端点标注力度值；默认只描最近一个，勾选「显示全部背驰段」可全出）。从任一列表点「查看结构」进入后，可直接 **← / → 切换上一只、下一只**（沿用该列表当前排序顺序，工具栏显示「第 n/N 只 · 来源」），`Esc` 返回来源列表
- **关注圈**：仍在跟踪的股票（待二买 / 弱跟踪 / 机会已触发），**一买失败与二买失败即剔除出圈**；工具栏显示「在圈 N 只 · 已出圈 M 只」，点**「重评关注圈」**用本地 K 线缓存重跑一遍（不联网，约 1~2 秒）
- **三日买卖点池**：最近 3 个交易日内触发的信号，按一买池 / 二买池 / 三买池 + **一卖风险 / 二卖风险** 分组展示

## 历史买点成功率

分两套口径，**不要混用**：

| 口径 | 入口 | 数据来源 | 回答什么问题 |
|---|---|---|---|
| **全市场** | 市场页成功率面板 | `watchlist` 表（关注圈状态流转） | 全市场一买/二买的历史表现 |
| **个股自身** | 个股查询页结论区 | `signals` 表按时间线重新配对 | **「这只票我一买成功率几何」** |

### 个股口径的判定规则

- **一买成功** = 该次一买之后 `max_wait_bars`（30）个**交易日内**出现二买
- **二买成功** = 该次二买之后 30 根内收盘未跌破二买低点
- **样本 < 3 次不给百分比**，只列逐次明细——1 次成功记成 100% 会严重误导
- 没有历史信号时返回「暂无历史」，**不给 0%**

### 信号去重（重要）

`signals` 表的信号身份是 `(symbol, kind, period, trade_date, price, anchor_price)`，
**不含 `bar_index` / `anchor_index`**——后者是「K 线窗口内的相对位置」，
用户传 `days=600` 与 `days=400` 时同一个信号下标不同，用它做唯一键会让
同一信号被反复插入。库内历史曾因此产生 15416 条重复（占 36%），已清理。

配对一买与二买时也必须用**交易日序**（信号日在 K 线序列中的位置），不能相减
`bar_index`——两次不同扫描写下的信号相减会算出错误间隔。

> **升级提示**：老库首次打开会自动去重并重建 `signals` 约束（218 万行量级约几秒）。
> 去重后个股历史次数会从虚高值回落到真实值，全市场成功率不变。

### 全市场口径的判定规则

- **一买成功率** = 一买入圈后最终引出二买的比例。分母 = 已终结的一买记录（机会已触发 + 二买失败 + 一买失败 + 弱跟踪），仍在「待二买」的记录单列为进行中、不计入分母
- **二买成功率** = 二买确认后，在 `max_wait_bars`（默认 30 根）考验窗口内守住二买低点的比例。窗口之外的破位不计失败（可能是后续大盘整体回落，记在这笔二买头上会把成功率做虚）

> 二买失败只能在**后续 K 线**上观测到，而关注圈记录是历次扫描沉淀的。新增交易日后需点一次「重评关注圈」才会把该失败的记录翻状态。

## 缠论信号口径

买点用于**选股**，卖点用于**持仓风险提示**。两者语义不同，因此卖点不参与「是否符合买入条件」的判定，而是单独放在 `risk_signals` / `/api/market/risk` 中。

### 买点（参与选股）

- **一买（入圈）**：连续下移低点的下跌段中，末段 MACD 柱面积相对前段衰减（背驰度 > 5%），低点位于最近中枢 ZD 下方，底分型确认次日为信号日
- **二买（机会提示）**：一买后出现向上段，首次回调不破一买低点，回调段力度相对上涨段衰减，底分型确认次日触发
- **三买（趋势延续）**：中枢完成后出现向上离开笔（终点 > 中枢上沿 ZG），其后回调终点仍 > ZG（未跌回中枢），回调力度相对离开笔衰减，底分型确认次日触发
- **失效**：收盘跌破一买低点 → 出圈「一买失败」；二买确认后 `max_wait_bars`（默认 30 根）内收盘跌回二买低点 → 出圈「二买失败」；入圈 30 根 K 线未出二买 → 降级「弱跟踪」

### 卖点（仅风险提示）

- **一卖（顶背驰）**：连续上移高点的上涨段中，末段 MACD 柱面积相对前段衰减（顶背驰度 > 5%），且高点位于最近中枢 ZG 上方；顶分型确认次日触发，提示「留意减仓」
- **二卖（反弹不创新高）**：一卖之后出现下跌段，其后的反弹段**未超过一卖高点**，且反弹力度相对下跌段衰减；反弹顶分型确认次日触发

### 通用约定

- 信号一律按「确认日」计算（`bar_index = 分型索引 + 1`），历史信号不复核改判（防未来函数）
- 关键点位（图表箭头、`anchor_price`）指向**顶/底分型本身**，而不是确认 K 线
- 每类信号的 `meta` 都带 `previous_segment` / `current_segment`（两段笔的起止索引与价格、方向），供前端把背驰比对的两段原样描出来；老数据没有这两个字段时前端判空跳过

## 关注圈状态机

```
一买入圈 → WAIT_SECOND_BUY ──┬─ 二买确认 ─────────────→ OPPORTUNITY ──┬─ 窗口内破二买低点 → SECOND_BUY_FAILED（出圈）
                            │                                        └─ 窗口内守住 → 留在圈内
                            ├─ 跌破一买低点 ───────────────────────→ FAILED（出圈）
                            └─ 超过 max_wait_bars 未出二买 ────────→ WEAK_TRACK
```

`OPPORTUNITY` **不是终态**：二买确认之后价格仍可能跌回二买低点，必须继续参与后续扫描的判定，否则「二买失败」永远观测不到。出圈是**软剔除**——记录仍留在库里供成功率统计，只是不再出现在 `/api/watchlist`。

## 多周期（日线 / 30分钟 / 15分钟）

- **日线是选股主周期**：市场扫描、关注圈状态机、买卖点池默认全部基于日线
- **分钟级别只做区间套确认与日内择时**：不参与选股判定，也不改写日线关注圈状态
- 数据源限制（实测，非估计）：日线可取约 400 根；**分钟周期仅保留约 1 个月，实际可得 30 分钟约 72 根、15 分钟约 96 根（≈9 个交易日）**。因此分钟级别无法做全市场选股，只能做单只/少量标的的分析
- 分钟周期取数必须用 `--start/--end`（`--limit` 对分钟周期无效），且连续取数会触发数据源限流，已内置退避重试
- 存储层 `bars` 与 `signals` 均带 `period` 列，三个周期的数据互相隔离；老库首次打开会自动迁移并把存量数据回填为 `period='day'`

## 缠论背驰判定（按《教你炒股票108课》原文口径）

> 实现见 `src/chanpicker/effort.py`，回归用例见 `tests/test_effort.py`。
> 下文页码均指张星星注解版 PDF。

### 力度：三个合法口径

| 口径 | 定义 | 原文依据 |
|---|---|---|
| **同色柱逐片面积** | MACD 柱按红/绿切分成「片」，只累加同色 | p125「**肯定是片和片比**」 |
| 趋势平均力度 | 面积 ÷ 持续根数 | p408 |
| 均线偏离（有向） | 收盘价对均线的最大**带符号**偏离 | 「缠中说禅走势力度」的代理项 |

末片（仍在伸长那片）按 **p295** 折算：已出现面积 ×2 当作该段面积，这样最后阶段就能判出背驰。

> 注意：MACD 柱 = DIF − DEA，**不乘 2**。软件里常见的 ×2 只是显示需要，
> 乘了会让所有面积口径整体翻倍，阈值完全对不上。

### 背驰三条件（p368）

> 「黄白线不创新高/新低 **或** 柱子面积变小，**两个出现一个就要注意，两个都出现更标准**」

| # | 条件 | meta 字段 |
|---|---|---|
| ① | DIF/DEA 不创新高（新低） | `dif_weaker` |
| ② | 同色柱面积变小 | `area_weaker` |
| ③ | 均线不创新高（新低） | `ma_weaker` |

**任一成立即背驰**；②与③同时成立记为**标准背驰**（`standard: true`）。

另外还有一道收紧（p116 第 15 课《没有趋势没有背驰》）：

> 「**没有趋势，没有背驰。在盘整中是无所谓『背驰』的**。」

所以一买/一卖只取**趋势背驰**——背驰段之前必须已有**两个依次同向的中枢**，
只有一个中枢（盘整）里的背驰不算。

阈值参数（`ChanConfig`，默认值 0 = 最宽松，与旧口径一致）：

```python
require_standard_divergence   # 只取标准背驰（②③同时弱）。默认 True
require_trend_context         # 只取趋势背驰（p116）。默认 True
divergence_dif_margin         # DIF/DEA 需越过的绝对容差
divergence_area_margin        # 面积至少还要缩这个比例才算弱（0.05 = 需缩 5%）
divergence_ma_margin          # 均线需越过的绝对容差
ma_period                     # 均线周期，默认 20
```

### 中枢与买卖点的层级（p152 / p1351）

> **p152**：「某级别走势类型中，被**至少三个连续次级别走势类型**所重叠的部分，称为中枢。」
> 对**最后不能分解的级别**（我们的日线图），定义为「至少三个该级别单位 K 线重叠部分」。
> **p1351**：「笔不能构成中枢」。

因此引擎把**中枢与全部买卖点都放在「次级别走势类型」这一层**判定
（`ChanConfig.use_canonical_zhongshu=True`）。早期版本中枢用段、买卖点用笔，
两套索引对不上——实测中枢终点在 index 11、向上突破笔起点在 index 10，
三买的「起点 >= 中枢终点」永远匹配不上，信号静默消失。

| 层级 | 实现 | 说明 |
|---|---|---|
| 次级别走势类型段 | `structure.build_legs` | 每 `min_legs_bars`（默认 3）根 K 线一段 |
| 中枢 | `structure.detect_zhongshu_by_legs` | 三段重叠，`ZG=min(高)`、`ZD=max(低)`（p167），支持延伸 |
| 一买 | 下跌趋势的标准背驰 | p116 趋势限定 + p368 标准背驰 |
| 二买 | 一买后**第一次**次级别回调不破一买低点 | p152-153 |
| 三买 | 中枢后向上离开，**第一次**回抽不跌破 ZG | p208 定理 + p590 |
| 一卖 / 二卖 | 上述的镜像 | |

> 段粒度比笔粗，候选对更多，所以「标准背驰 + 趋势背驰」两道收紧是必需的：
> 实测 800 只股票，不收紧时一买 14.2 个/股，收紧后 **2.3 个/股**（旧笔口径是 2.4）。

### 缠论原文之道（p84 / p98）：均线买卖系统的体位与吻

> 实现见 `src/chanpicker/masystem.py`，回归见 `tests/test_masystem.py`。

前面讲的是「术」（背驰怎么算、中枢怎么划）。但缠论说一买的定性首先是「道」——
**买点不是一个「形态达标就买」的技术信号，而是「体位 + 次数 + 位置」的组合判定**。

**p84 · 第12课《一吻何能消愁？》——分类与应对，「道」的骨架**
> 「对于任何走势，**首要判断的是体位：男上位还是女上位**。」
> 「买的方式明白了，**卖就反过来就可以了**。」

**p98 · 《买入卖出机制（1）》——买卖点的原文定性**
> 「第一类买点：由**男上位最后一吻后**出现的**背驰式下跌**构成。」
> 「第二类买点：**女上位第一吻后**出现的下跌构成。」
> 「这第一吻后的下跌一般不会构成买点，**必须是至少第二吻以后**。」

**三种吻（p98）**：飞吻（走平后续原趋势）、唇吻（靠近但不穿越）、湿吻（跌破/升破或反复缠绕）。

| 买点 | 原文定性（p98） |
|---|---|
| **一买** | 男上位 · **最后一吻之后** · 背驰式下跌 · 低点破中枢 ZD |
| **二买** | 女上位 · **第一吻之后** · 下跌 · 不破一买低点 |
| **一卖** | 一买镜像：女上位 · 最后一吻之后 · 背驰式上涨 |
| **二卖** | 二买镜像：男上位 · 第一吻之后 · 反弹 · 不破一卖高点 |

```python
use_ma_system          # 启用均线买卖系统（体位 + 吻），默认 True
enforce_ma_rules       # True=规则不满足就不出信号；False=仍出信号但记下差在哪
ma_short_bars          # 短期均线周期（原文 5 日）
ma_long_bars           # 长期均线周期（原文 10 日）
ma_tangle_threshold    # 缠绕阈值 |短期-长期|/长期，默认 0.01
ma_min_male_kisses      # 男上位至少几吻才认一买。原文是 2；默认 1（一吻也认，放宽）
```

放宽点与理由：原文 p98 说「**必须是至少第二吻以后**」，默认取 **1**（一吻也认），
因为星注明确留了口子——「如果将第一吻前面部分走势拿过来组合，就可以形成一个与
下方同级别的箱体，所以也可以形成趋势一买」。要严格口径把它改成 2 即可。

信号 meta 里带完整判定依据：

```json
"rule_kind": "FIRST_BUY", "rule_satisfied": true, "rule_position": "male",
"rule_kiss_index": 12, "rule_male_kisses": 1,
"rule_reasons": ["男上位（p84：首要判断体位）", "男上位第 12 吻之后（2026-07-08 结束）出现背驰下跌"],
"rule_violations": []
```

> `rule_male_kisses` 数的是**本轮**男上位的吻数，不是全程累计——
> 遇到异体位的吻就重新计数。这点踩过坑：用累计数会让第一轮男上位的第一个吻
> 之后被误判成「已经过多吻」，把该拒的信号放行。

## 数据源

腾讯自选股（westock CLI）：前复权（qfq），批量拉取（每批 ≤20 只，限流自动退避重试），SQLite 增量缓存。

可用周期：`day`（默认，≈400 根）、`m30`（≈72 根）、`m15`（≈96 根）。

## 买点池口径

「三日买卖点池」的统计窗口是**最近 N 个交易日**（取自本地日线缓存的日期集合），不是自然日；数据来自 signals 表（全部已扫描标的），同一标的同一信号类型只保留最近一条。同一次回调可能同时满足二买与三买定义，此时会同时出现在两个池中。

> 升级提示：旧版本的信号表里没有卖点记录，升级后需**重新执行一次市场扫描**才会生成卖点，风险池才会非空。

## 存储与性能

SQLite（WAL 模式）单文件存储，实测 218 万根 K 线约 450 MB。查询模式是**点查 + 小范围扫描**（单股取 400 根 K 线 ≈ 0.7 ms），不是跨股分析。

三条关键设计，改动前务必读：

1. **`bars(period, trade_date)` 覆盖索引不能删**。`recent_trading_dates`（`SELECT DISTINCT trade_date ... WHERE period=?`）和 `period_counts`（`GROUP BY period`）只按 period 过滤，如果索引前导列是 symbol 就用不上，会全扫 218 万行——实测 8990 ms / 7809 ms，页面首屏要等 12–20 秒。加上 `(period, trade_date)` 后降到 **0.24 ms / 61 ms**。
2. **`symbol_names()` 批量查名，不要退回逐行 `symbol_name()`**。候选表近万条、关注圈四千条，逐行补名就是 N+1。批量按 500 分批（SQLite 变量上限 999）。
3. **所有访问 `self._conn` 的方法必须带 `@_sync`**。sqlite3 连接非线程安全，FastAPI 同步端点跑在线程池里。

回归用例：`tests/test_query_performance.py`（索引存在性 + 查询计划 + 批量次数计数）。

**信号身份不含 `bar_index` / `anchor_index`**。它们是 K 线窗口内的相对位置，
用户传 `days=600` 与 `days=400` 时同一个信号下标不同，用作唯一键会让同一信号
被反复插入（库内曾有 15416 条这样的重复）。唯一键是
`(symbol, kind, period, trade_date, price, anchor_price)`，见 `Store.SIGNAL_IDENTITY_COLUMNS`。
