## 服务器 Python 3.9 兼容改造（部署踩坑）

- 用户在服务器执行 `python3 -m venv .venv && pip install -e .` 报 `Package 'chanpicker' requires a different Python: 3.9.25 not in '>=3.11'` —— 项目 `requires-python` 写死 `>=3.11`，服务器是 3.9.25。
- 处理：`requires-python` 放宽为 `>=3.9`，并把全部 PEP 604 联合类型（`X | None` / `X | Y`）改成 `Optional[...]` / `Union[...]`（core/cli/app/service/provider/store 六个文件）。**必须改的原因**：即使有 `from __future__ import annotations`，FastAPI 在注册路由时会用 `get_type_hints` 真正求值签名标注，3.9 上 `str | None` 直接 TypeError。
- 未改动 PEP 585 内置泛型（`list[str]`/`dict[str, Any]`），3.9 已原生支持。
- 验证方法：用 `uv python install 3.9` 装 3.9.25，建 `/tmp/venv39`，`PYTHONPATH=src` 跑 12 个单测全过，并以 3.9 启动服务验证 `/api/health`、`/api/market/pools`、`/api/market/scan/status?run_id=`（Optional 查询参数）、`/api/signals/history` 全部正常。
- 环境坑：本机 `pip install -e .` 在任意 Python 下都失败于 `setuptools editable_wheel` 的 `dist_dir.mkdir` → 被 WorkBuddy 沙箱 shim（`sitecustomize.py` `_brokered_path_mkdir`）拦截报 EEXIST；与项目无关。绕法：用 `PYTHONPATH=src` 直接跑，不依赖可编辑安装。换 TMPDIR / 关沙箱 / 降 setuptools 到 75.3.0 均无效。
- 文档已同步：DEPLOY「服务器环境要求」改为 3.9+，FAQ 增加该报错条目；README 增加环境要求段。

## 修正 westock 安装与授权文档（用户指出「这个不对」）

- 原 DEPLOY 写的 `bash /path/to/westockdata/scripts/setup.sh` 与「`westock auth status` 会输出链接」不准确/不可执行。查证 `westockdata` 技能包 SKILL.md + scripts/setup.sh + references/auth.md 后重写。
- 真实事实：
  - 安装入口有三个：`bash scripts/setup.sh`（macOS/Linux）、`powershell setup.ps1`（Windows）、`node scripts/setup.cjs`（Node≥18），**均在技能包 `westockdata/scripts/` 目录内**；服务器默认没有该包，需 `scp` 脚本过去跑，或本地装好后把单文件二进制 `~/.local/bin/westock` 拷到 `/usr/local/bin`。
  - setup.sh 零参数执行，自动识别 linux/darwin × amd64/arm64，强制 SHA256 校验，**只写二进制、不改 PATH/不写 shell 配置**，默认装到 `~/.local/bin`（`WESTOCK_INSTALL_DIR` 可覆盖）。
  - 授权是设备码流程：`westock auth status` → `READY` / `AUTH_REQUIRED:<url>`（5 分钟有效，任意电脑浏览器打开）→ 轮询 `westock auth fetch` 直到 `TOKEN_READY`；**轮询期间禁止再跑 `auth status`**（会重新 issue 覆盖 device code，导致刚扫的码作废）。兜底 `westock auth set "<key>"`，退出 `westock auth clear`。
  - 凭证在 `~/.westock`（`WESTOCK_HOME` 可覆盖），systemd 必须同用户。
- 代码顺带加固：`provider.WESTOCK_BIN_CANDIDATES` 增加 `/usr/local/bin/westock`（服务器常见安装位）。
- systemd unit 文档补 `Environment=WESTOCK_HOME=` 与 PATH 含 `/home/chanpicker/.local/bin`。

## 「命令行能查行情、服务却报未授权」的诊断能力

- 现象：用户 root 下 `westock quote sh600519` 返回真实行情，但 health 仍 `westock_authorized:false`。
- 排查结论：health 实际执行的是 `westock quote sh000001`（本机实测正常），所以不是命令问题，而是**服务进程的用户/HOME 与授权用户不一致**，服务侧的 CLI 找不到 `~/.westock` 凭证，输出 AUTH_REQUIRED。
- 代码改动：`backend/app.py` health 增加自诊断字段 `westock_bin` / `westock_home` / `service_user`（getpass.getuser，失败回落 uid）/ `westock_detail`（未授权时的原始报错前 300 字）。这样下一次同类问题可自证，不必来回问。
- DEPLOY FAQ 增加「用户不一致排查」小节：给出 `ps -o user=,pid=,cmd= -C uvicorn` 与 `sudo -u <服务用户> -H westock auth status` 的判定流程。
- 用户确认服务以 root 运行 → 补充「root 部署授权」逐步流程，并在 systemd unit 里**显式写死 `HOME=/root` 与 `WESTOCK_HOME=/root/.westock`**（不要靠继承，最稳）；同时注明改 `User=chanpicker` 时两处必须同步改且需换用户重授权。
