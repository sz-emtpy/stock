# 服务器部署说明（批次 2-7）

## 问题原因

服务器上是旧代码，缺 `src/chanpicker/masystem.py`（批次 5 新增）以及
`structure.py` / `effort.py` / `indicators.py`（批次 1、2、5 新增）。
`backend/service.py` 里新增了 `from chanpicker.masystem import ...`，
旧服务器上找不到该模块，启动即失败。

## 一、上传并解压

本包 `chanpicker-deploy.tar.gz` 保持原有目录结构，解压到项目根即可：

```bash
cd /opt/chanpicker
tar xzf chanpicker-deploy.tar.gz
```

## 二、清pyc 缓存（重要）

```bash
cd /opt/chanpicker
find . -name "__pycache__" -type d -exec rm -rf {} + 2>/dev/null
find . -name "*.pyc" -delete 2>/dev/null
```

不清的话旧的 `.pyc` 可能被复用，出现「明明传了新文件还是报旧错」。

## 三、数据库会自动迁移，但先备份

`backend/store.py` 改了迁移逻辑，**启动时会自动执行**，无需手动跑。
但建议先备份：

```bash
cp data/chanpicker.db data/chanpicker.db.bak-$(date +%Y%m%d-%H%M%S)
```

### 本次迁移做了什么

1. `_migrate_legacy` 补`period` 列时，拷贝数据前**先去重**。
   老库里同一个信号可能被存过多次（`anchor_index` 随K线窗口长度漂移，
   旧唯一键拦不住），直接拷贝会撞 UNIQUE 约束导致启动失败。
2. 去重键里**不含 `period`**——那一段迁移时才刚补这列，引用它会报
   `no such column: period`。
3. 之后 `_migrate_signal_identity` 把信号唯一键升级为
   `(symbol, kind, period, trade_date, price, anchor_price)`。

**信号身份变了**：同一个信号在不同日期/价格下会各自成为独立记录。
关注圈里可能出现「同一段走势被记了多次」，但信号数量口径也同步变了，
成功率统计会随之变化——这是批次 2 以来一直在做的事，不是本次引入的问题。

## 四、重启并验证

```bash
cd /opt/chanpicker
.venv/bin/python -m uvicorn backend.app:app --host 0.0.0.0 --port 8787
```

另开一个终端验证：

```bash
curl -s http://127.0.0.1:8787/api/health
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8787/api/analyze?symbol=sh600000"
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8787/api/market/second-buy-confirmations?limit=5"
```

预期：全部 200。

### Python 3.9 兼容性

已用 3.9.25 跑过全部 270 个测试，无PEP 604（`X | None`）语法。
服务器是 3.9，可直接运行。

## 五、可选：启用每日分钟增量

```bash
cd /opt/chanpicker
PYTHONPATH=src:. .venv/bin/python scripts/sync_intraday.py --limit 50  # 先小批量试
PYTHONPATH=src:. .venv/bin/python scripts/sync_intraday.py          # 全量，约 41 分钟
```

cron（每交易日 17:30，与日线扫描错峰）：
```cron
30 17 * * 1-5 cd /opt/chanpicker && PYTHONPATH=src:. .venv/bin/python scripts/sync_intraday.py >> /var/log/chanpicker/intraday.log 2>&1
```

**注意**：分钟数据源只回约 10 个交易日，这个脚本只能让**未来的**二买具备
p100 买点定律的验证条件，补不回历史。
